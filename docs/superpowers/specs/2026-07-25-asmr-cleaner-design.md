## 一、项目概述

ASMR-Cleaner 是一个 Python 桌面工具，专门处理 ASMR 直播回放音频。核心逻辑不是常规降噪，而是**以极低阈值检测并切除长段静音/死区**，在拼接点做交叉淡入淡出，确保耳语、触发音等低音量内容不受损伤。

### 核心原则

1. **无损处理**：内部全用 PCM（float32 归一化）运算，默认输出 WAV，绝不降低音质
2. **轻量化**：依赖最小化，打包后单文件 `.exe` 可分发
3. **人性化**：中文界面，清晰的错误提示，格式化日志报告
4. **可追溯**：每次处理生成永久 JSON 日志，记录所有切除详情

---

## 二、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 音频解码/编码 | pydub（底层 ffmpeg） | API 简洁，全格式覆盖 |
| 核心运算 | numpy（float32 归一化数组） | 已有环境，向量化高效 |
| GUI | tkinter + ttk（clam 主题） | Python 自带，零额外依赖 |
| 打包 | PyInstaller | 单文件 .exe，含 Python runtime + ffmpeg |
| 并发 | threading + queue | 后台处理不冻结 UI |

### 不选型的理由

- **librosa**：功能丰富但安装包 >100MB，违背轻量化
- **soundfile**：不支持 MP3，需额外桥接代码
- **纯标准库 wave**：仅支持 WAV，用户需预先转格式，体验差

## 四、核心处理流程

```
                                                  ┌─────────────────┐
输入文件 ──→ audio_io.decode()                     │  silence_       │
           │  解码为 PCM float32, 记录元信息         │  detector       │
           ▼                                        │                 │
    ┌──────────────┐                                │ 分块读取 PCM    │
    │  第 1 遍扫描  │────→ silence_detector.scan()   │ 逐块计算 RMS    │
    │  (分析阶段)   │     返回静音区间列表             │ 滞后窗口判定    │
    └──────┬───────┘                                │ 输出区间列表    │
           │                                        └─────────────────┘
           ▼
    ┌──────────────┐
    │  第 2 遍导出  │────→ core.process()            ┌─────────────────┐
    │  (处理阶段)   │     跳过静音区间                 │  拼接点         │
    └──────┬───────┘     拼接处做 crossfade          │  crossfade()    │
           │             流式写入输出文件              │  重叠叠加法     │
           ▼                                         │  30ms 默认      │
    ┌──────────────┐                                └─────────────────┘
    │  audio_io    │────→ audio_io.encode()
    │  .encode()   │     写入输出文件（WAV 默认）
    └──────┬───────┘
           │
           ▼
    ┌──────────────┐
    │  log_writer  │────→ 写 JSON 日志
    │  .write()    │     原子写入（.tmp → rename）
    └──────────────┘
```

### 4.1 静音检测算法

```
输入: PCM float32 数组 [-1.0, 1.0], 采样率
参数: threshold_db (默认 -55), min_duration_sec (默认 5.0), hysteresis_ms (固定 200)

算法:
  frame_size = 1024 样本
  逐帧计算 RMS → 转换为 dB

  状态机: STATE_ACTIVE / STATE_SILENCE
  从 ACTIVE → SILENCE: RMS < threshold_db 持续 ≥ min_duration_sec
     （hysteresis_ms 缓冲防止阈值边缘抖动）
  从 SILENCE → ACTIVE: RMS ≥ threshold_db 持续 ≥ hysteresis_ms
```

**防抖保护**：上下穿过阈值各需要 200ms 滞后窗口，防止阈值边缘的来回震荡把静音区切碎。

**RMS 的 dB 换算**（float32 归一化域）：
```
dB = 20 × log10(max(rms, 1e-10))
```

`1e-10` 的下限防止 `log10(0)` → `-inf`。

### 4.2 Crossfade 实现

**正确的重叠叠加法**（非顺序 fade_out + fade_in）：

```
设前段为 A（N 帧），后段为 B（M 帧），crossfade 长度为 L 帧

重叠区 = A 的尾部 L 帧 + B 的头部 L 帧

对 i ∈ [0, L):
  w_out = 1.0 - i/(L-1)      # 线性淡出权重
  w_in  = i/(L-1)            # 线性淡入权重
  result[i] = A[N-L+i] × w_out + B[i] × w_in

最终输出 = A[0:N-L] + result[0:L] + B[L:M]
```

两个拼接权重在任何时刻的和恒为 1.0，功率不变，不会出现"凹陷"。

### 4.3 内存策略（v1 务实方案）

**现实约束**：pydub 的 `AudioSegment.from_file()` 会将整个文件解码到内存。3 小时 48kHz 立体声 16bit ≈ 2GB 内存占用。

**v1 策略**：接受全量加载，做好保护：

| 措施 | 说明 |
|---|---|
| 加载前检查文件大小 | >2GB 时弹出确认对话框，告知预估处理时间 |
| 解码后立即转为 numpy float32 | pydub AudioSegment 释放，只保留一个数组（~原始大小） |
| 两遍逻辑在 numpy 数组上进行 | 第 1 遍扫描静音区间（纯索引操作），第 2 遍切片写文件 |
| 垃圾回收 | 每阶段完成后显式 `gc.collect()` |

**内存开销估算**：
- 3 小时 48kHz 立体声 16bit：`48000 × 2 × 2 × 10800 = 2.07 GB`
- 转为 float32 后：`48000 × 2 × 4 × 10800 = 4.15 GB`
- 现代 8GB+ RAM 的电脑可以承受

**v2 改进方向**：通过 ffmpeg subprocess 管道实现真正的流式分块读取，将内存占用降至 ~100MB 以内，支持任意长度音频。

| 阶段 | 说明 |
|---|---|
| 加载 | 解码输入文件，验证格式 |
| 分析 | 第 1 遍扫描，检测静音区 |
| 处理 | 第 2 遍导出，切除静音 + crossfade |
| 导出 | 写入输出文件 |
| 日志 | 生成 JSON 日志 |

### 5.4 线程模型

```
主线程 (GUI)                    后台线程 (Worker)
    │                               │
    │── 点击"开始处理"               │
    │── 禁用按钮                    │
    │── 启动 Worker 线程 ──────→    │── core.process()
    │                               │── 通过 queue.put() 发送进度
    │                               │
    │── after(100ms) 轮询 queue ←── │
    │── 更新进度条/阶段/状态         │
    │                               │
    │── Worker 完成 ←────────────   │── 结果或异常放入 queue
    │── 恢复按钮                    │
    │── 显示完成/错误信息            │
```

**铁律**：后台线程绝不直接操作 tkinter 控件，只通过 `queue.Queue` 发消息。

## 七、错误处理矩阵

| 场景 | 检测方式 | 用户可见行为 |
|---|---|---|
| 未选文件 → 点"开始处理" | 按钮在无文件时置灰 | 无需处理，按钮不可点 |
| 选了不支持格式 | audio_io.decode() 抛出 | 弹窗："不支持的文件格式 .m4a。支持的格式：WAV, MP3, FLAC, AAC, OGG" |
| 文件损坏/解码失败 | ffmpeg 返回错误 | 弹窗："无法解码文件，文件可能已损坏" |
| 文件过大（>4GB） | 加载前检查文件大小 | 弹窗警告："文件较大（X.XX GB），处理可能需要较长时间。是否继续？" |
| 处理中用户关闭窗口 | WM_DELETE_WINDOW 事件 | 弹窗："正在处理中，确定要退出吗？" → 确认后终止线程 |
| 扫描完成无静音区 | removed_segments 为空 | 状态栏："✅ 扫描完成，未发现长静音区，无需处理" |
| 整个文件几乎全是静音 | 保留段总时长 < 原始 5% | 弹窗："⚠️ 检测到整个文件几乎都是静音（保留率 < 5%），请确认是否选错了文件" |
| 输出文件已存在 | os.path.exists() | 弹窗："输出文件 xxx_cleaned.wav 已存在。是否覆盖？[覆盖] [取消]" |
| 磁盘空间不足 | 写入时 OSError | 弹窗："磁盘空间不足，无法写入输出文件" |
| 处理崩溃 | 顶层 try/except | 弹窗："处理出错：[错误信息]。日志已部分保存"；不丢崩溃前的日志 |

## 九、人性化设计要点

1. **i18n 后门**：所有文本走 key 查找，加语言只需新字典，UI 零改动
2. **白话说明**：参数旁的 `[?]` 按钮使用日常语言解释，不出现"RMS"、"dBFS"等技术术语
3. **按钮状态管理**：可点击/不可点击有清晰的视觉差异
4. **状态栏**：始终显示当前在做什么，不让用户猜测
5. **完成后的引导**：处理完成后提供"打开文件位置"按钮，而不是让用户自行寻找
6. **日志可读性**：JSON 是给机器读的，日志查看弹窗是给人读的——用表格和自然语言表述
7. **最小窗口尺寸**：800×600，防止布局挤压变形
8. **高 DPI 兼容**：启动时设置 DPI 感知

## 九、参数默认值

| 参数 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| 静音阈值 | -55 dB | -90 ~ -20 dB | 低于此音量的部分被视为静音 |

### PyInstaller 打包注意事项

- `--add-binary` 包含 ffmpeg.exe
- `sys._MEIPASS` 路径查找 ffmpeg
- pydub 中设置 `AudioSegment.converter = os.path.join(base_path, "ffmpeg.exe")`
- 目标：单个 `.exe`，用户下载即用，无需安装任何运行环境
