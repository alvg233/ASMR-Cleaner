# 从零到一开发一个软件的全流程

> 以这个 ASMR Cleaner 项目为例，一步步告诉你整个过程是怎么走的。没有术语，只说人话。

---

## 整个流程一共 8 步

```
  [1] 想清楚要做什么
   ↓
  [2] 做技术选型（用什么做）
   ↓
  [3] 设计软件结构（几个文件、怎么分工）
   ↓
  [4] 写实现计划（拆成小任务）
   ↓
  [5] 一个一个任务写代码
   ↓
  [6] 真机上测试、修 bug
   ↓
  [7] 打包成 exe 给别人用
   ↓
  [8] 上传到 GitHub / Gitee
```

下面每步都拆开讲。

---

## 第 1 步：想清楚要做什么

**不要一上来就写代码。** 先想清楚三件事：

### 1.1 这个软件给谁用？干什么？

```
这个项目：给看 ASMR 直播回放的人用，切除长时间静音段。
```

### 1.2 输入什么、输出什么？

```
这个项目：
  输入：音频文件（WAV / MP3 / FLAC 等）
  输出：处理后的音频文件 + 一份处理日志（JSON）
```

### 1.3 核心功能是什么？边界在哪？

```
这个项目：
  ✅ 检测长段静音（超过 5 秒）
  ✅ 切除静音段
  ✅ 拼接处平滑过渡（淡入淡出）
  ✅ 生成处理日志
  ❌ 不做 AI 降噪（不属于静音切除）
  ❌ 不做视频处理（只处理音频）
  ❌ 不做实时处理（只处理录播文件）
```

**这一步的要点**：把"要做"和"不做"都写清楚。很多项目做不完就是因为范围越来越大。

---

## 第 2 步：技术选型（用什么做）

这一步就是回答一个问题：**我需要哪些现成的轮子？**

### 2.1 核心功能用什么？

```
需求：读音频、处理音频数据、写音频
选项：
  - pydub（轻量，50KB）
  - librosa（功能多但安装包大，100MB+）
  - 纯自己写（只能处理 WAV，其他格式不支持）

这个项目选了：pydub
原因：最轻、支持格式最多、代码最少
```

### 2.2 界面用什么？

```
需求：做一个桌面软件，有按钮、有进度条、能选文件
选项：
  - tkinter（Python 自带，不需要装任何东西）
  - PyQt（功能强但体积大，打包后多 50MB）
  - 网页界面（需要浏览器，不够"桌面"）

这个项目选了：tkinter
原因：自带 + 够用 + 打包体积小
```

### 2.3 数据处理用什么？

```
需求：做数组运算（分帧、算 RMS、切片拼接）
选项：numpy（没有替代品）

这个项目选了：numpy
原因：处理音频就是处理大数组，numpy 是唯一解
```

### 2.4 怎么打包给别人？

```
需求：打包成 exe，对方不用装 Python 就能运行
选项：PyInstaller（打包成单个 exe 文件）

这个项目选了：PyInstaller
```

### 小总结

选技术就一个原则：**能用简单的绝不用复杂的**。能用一个库解决的事绝不引入第二个。

---

## 第 3 步：设计软件结构

这一步画出"这个软件由哪些文件组成"。

### 3.1 核心原则：分层

```
┌─────────────────────┐
│     GUI 层           │  ← 界面：按钮、进度条、弹窗
│  (gui/ 文件夹)       │     只负责展示，不碰数据处理逻辑
├─────────────────────┤
│     引擎层           │  ← 逻辑：读音频、检测静音、拼接
│  (asmr_cleaner/ 文件夹)│   只负责干活，不碰界面
└─────────────────────┘
```

**为什么分两层？** 因为如果你以后想换界面（比如 tkinter → PyQt），只需改 GUI 层，引擎层一行不用动。反过来，如果你改算法，界面也不受影响。

### 3.2 引擎层（asmr_cleaner/）里面有什么？

```
asmr_cleaner/
├── audio_io.py          ← 读音频、写音频
├── silence_detector.py  ← 检测静音段
├── core.py              ← 把上面串起来：加载→检测→切除→保存
├── log_writer.py        ← 写处理日志（JSON）
├── i18n.py              ← 所有界面文字（中文/英文）
└── settings.py          ← 读写用户设置文件
```

**一个文件一个职责**。如果把所有功能写在一个文件里，改一个功能就要翻 2000 行代码——没人受得了。

### 3.3 GUI 层（gui/）里面有什么？

```
gui/
├── main_window.py   ← 主窗口（最大的文件，约 600 行）
├── widgets.py       ← 自定义控件（滑块+数字框的组合）
├── file_info.py     ← 显示文件信息的子面板
└── log_viewer.py    ← 弹窗显示处理日志
```

---

## 第 4 步：写实现计划（拆任务）

现在你有了整体结构，但一口气写完 14 个文件是不可能的。所以要**拆成小任务**。

### 拆任务的规则

1. 每个任务只改 1-2 个文件
2. 每个任务做完后能**独立验证**（import 不报错、跑个简单测试）
3. 任务之间有依赖关系（先做底层再做上层）

### 这个项目的 14 个任务

```
任务 1:  建项目骨架（创建文件夹、装依赖）
任务 2:  写翻译模块（i18n.py）
任务 3:  写设置模块（settings.py）
任务 4:  写音频读写（audio_io.py）
任务 5:  写静音检测（silence_detector.py）
任务 6:  写核心引擎（core.py）—— 串起 4+5+7
任务 7:  写日志模块（log_writer.py）
任务 8:  写自定义控件（widgets.py）
任务 9:  写文件信息面板（file_info.py）
任务 10: 写日志查看弹窗（log_viewer.py）
任务 11: 写主窗口（main_window.py）—— 串起 8+9+10
任务 12: 写入口文件（main.py）
任务 13: 端到端测试（造一段假音频，跑完整流程）
任务 14: 写 README 文档
```

注意顺序：**先引擎后 GUI，先底层后上层**。引擎层（2-7）写完可以先在 Python 命令行里测试，不用等 GUI。

---

## 第 5 步：写代码

这是大家最怕的一步——但其实按顺序来一点都不难。

### 5.1 写每个任务的方法：最小可跑单元

**别一口气写完整文件再跑**。比如你要写 `silence_detector.py`（静音检测）：

```python
# 步骤 1：先写一个函数，只处理最简单的情况
import numpy as np

def calc_rms_db(frame):
    """算一帧的 RMS 音量，转成 dB"""
    rms = np.sqrt(np.mean(frame ** 2))
    return 20 * np.log10(max(rms, 1e-10))

# 步骤 2：立即测试
if __name__ == "__main__":
    # 造一段假数据
    silent = np.zeros(1024)           # 纯静音
    loud = np.ones(1024) * 0.5        # 有声音
    print(f"静音: {calc_rms_db(silent):.1f} dB")
    print(f"声音: {calc_rms_db(loud):.1f} dB")
    # 输出：静音: -200.0 dB  声音: -6.0 dB
```

**跑通了再往下加**。每次只加 5-10 行，跑通再继续。如果一口气写了 100 行再跑，报 5 个错——你都不知道哪个先修。

### 5.2 先搭骨架，再填肉

比如写 GUI 主窗口，先这样：

```python
# 步骤 1：先搭一个空白窗口跑起来
import tkinter as tk
root = tk.Tk()
root.title("test")
root.mainloop()   # ← 黑色空白窗口弹出来了！第一步成功
```

```python
# 步骤 2：加一个按钮
btn = tk.Button(root, text="点我", command=lambda: print("点了"))
btn.pack()        # ← 按钮出现了！能点！第二步成功
```

```python
# 步骤 3：加一个文件选择功能
from tkinter import filedialog
def browse():
    path = filedialog.askopenfilename()
    print(f"选中了: {path}")

btn2 = tk.Button(root, text="浏览...", command=browse)
btn2.pack()
```

**每次只验证一件事。** 一个按钮能点、能弹对话框、能打印路径——这三步确认后，你才继续。

### 5.3 不知道怎么调用某个库？

不要问"帮我写代码"，要问"这个库怎么用"。

```
❌ "帮我用 pydub 加载音频文件"
✅ "pydub 怎么把 MP3 读成 numpy 数组？给我一个 5 行的例子"
```

第二种问法你得到的是**工具的使用说明**，第一种得到的是**你不理解的代码**。

## 第 6 步：真机上测试、修 bug

**AI 写完的代码必须在你自己的电脑上跑一遍。** 这个项目踩过的坑：

### 坑 1：emoji 炸了

```
现象：双击 exe 报错 "character U+1F4CB above range allowed by Tcl"
原因：tkinter 是老技术（Tcl/Tk），不支持 📋 之类的新 emoji
修复：把所有 emoji 换成纯文字
```

**这种坑 AI 不会告诉你**——因为 AI 是 Linux 服务器上跑的，不运行 Windows exe。必须你自己试。

### 坑 2：文件体积爆炸

```
现象：打包后 exe 243MB（去掉 ffmpeg 后），启动要 3 秒
原因：Anaconda 的 numpy 捆绑了 Intel MKL 数学库（500MB）
修复：用 pip 版 numpy（OpenBLAS，30MB）→ exe 降到 22MB，秒开
```

**原因**：AI 不知道你的 Python 环境装了什么。my 环境（Linux）和你的（Windows + Anaconda）完全不同。

### 坑 3：处理大文件时界面卡死

```
现象：点"浏览"选文件后窗口直接未响应
原因：读文件元信息时把整个音频解码到内存
修复：改用 ffprobe 读元信息（只读文件头，80ms 返回）
```

**为什么 AI 没发现**：AI 用 10 秒的测试文件没问题，你用 3 小时的直播回放就炸了。时间和数据量放大了问题。

### 修 bug 的正确姿势

```
1. 复现（确认不是偶发）
2. 看报错信息（不要跳过，每行都读）
3. 定位到是哪个函数/哪行代码
4. 问 AI："这个函数在处理大文件时很慢，原因可能是？怎么优化？"
5. 改 → 跑 → 确认修好 → 继续找下一个
```

## 第 7 步：打包成 exe 给别人用

### 7.1 安装打包工具

```bash
pip install pyinstaller
```

### 7.2 写打包配置文件

PyInstaller 需要一个 `.spec` 文件告诉它：
- 入口文件是哪个（main.py）
- 要不要打包 ffmpeg（不打包，放外边快得多）
- 排除哪些不需要的库（减小体积）

这个项目的 `build_onedir.spec` 已经写好了。

### 7.3 执行打包

```bash
python -m PyInstaller build_onedir.spec
```

产物：`dist/ASMR-Cleaner/` 文件夹，里面有一个 `ASMR-Cleaner.exe`。

### 7.4 补上必要文件

exe 不能独立工作——还需要 ffmpeg（解码音频）和 ffprobe（读元信息）。把这两个 exe 复制到同目录下。

### 7.5 打包成 zip 发给别人

```
ASMR-Cleaner.zip
├── ASMR-Cleaner.exe    ← 双击运行
├── ffmpeg.exe
├── ffprobe.exe
├── README.md
└── 使用说明.txt        ← 告诉别人"双击这个 .exe"
```

对方解压后双击 `.exe` 就能用，不需要装 Python，不需要装 ffmpeg。

## 第 8 步：上传到 GitHub / Gitee

### 8.1 先清理

```bash
# 删掉不需要上传的东西
# - build/  dist/  打包产物
# - .venv/         虚拟环境（别人自己装）
# - ffmpeg.exe     太大（在 .gitignore 里）
# - .idea/         IDE 配置
# - __pycache__/   Python 缓存
```

### 8.2 确定要上传的文件

```
应该上传的：
  ✅ 所有 .py 源代码
  ✅ requirements.txt（依赖清单）
  ✅ README.md（项目说明）
  ✅ build_exe.spec（打包配置）
  ✅ .gitignore（排除规则）
  ✅ docs/（文档）

不应该上传的：
  ❌ .venv/  build/  dist/
  ❌ ffmpeg.exe  ffprobe.exe（二进制，太大）
  ❌ .idea/  __pycache__/
```

### 8.3 上传

```bash
git remote add gitee https://gitee.com/你的用户名/仓库名.git
git push gitee master
```

### 8.4 上传发行版（zip 包）

去 GitHub/Gitee 网页上的 Releases 页面，把打包好的 zip 拖上去，写一段简介。

## 总结：8 步一张图

```
[1] 想清楚   →  输入什么、输出什么、什么能做、什么不做
[2] 选技术   →  能用简单的绝不用复杂的
[3] 画结构   →  一个文件一个功能，分层（引擎层 + GUI 层）
[4] 拆任务   →  每个任务改 1-2 个文件，做完能独立测试
[5] 写代码   →  每次只加 5-10 行，跑通了再往下
[6] 测试修bug →  必须在自己电脑上真跑，大文件、极端值都要试
[7] 打包     →  PyInstaller 打包成 exe + 外置 ffmpeg
[8] 上传     →  清理 → git push → 上传 zip 发行版
```

**最重要的一句话**：第 5 步"写代码"只是 8 步中的一步，前面 4 步决定了你写什么，后面 3 步决定了有没有人能用。软件工程不是写代码，是**从想法到能用的完整过程**。
